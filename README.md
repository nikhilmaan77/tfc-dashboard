# The Fresh Connection — results dashboard

An interactive dashboard presenting six rounds of *The Fresh Connection* supply-chain simulation, played by team **Not Fast, Just Furious** (GMBA October 26, Dr. Rajiv Aserkar).

The team went from **−13.61% ROI in Round 1 to +6.76% in Round 6**, with operating profit moving from −€549,532 to +€268,353. Demand was fixed for all seven rounds and contracted revenue never varied by more than 3.4%, so there was never a volume lever — the entire €817,885 improvement came from closing the gap between what was promised to customers and what the operation could actually deliver.

## Opening it

Open `index.html` in any modern browser. That's the whole thing — one file, no build step, no server, no install.

It also makes **no network requests at all**. No CDN, no web fonts, no analytics. It works with the wifi off, which matters when you're presenting from a classroom projector.

### Publishing to GitHub Pages

1. Push `index.html` and `README.md` to the repository root.
2. Settings → Pages → Source: *Deploy from a branch* → `main` / `/ (root)`.
3. The dashboard will be live at `https://<username>.github.io/<repo>/` within a minute or two.

| Key | View |
|---|---|
| `1` | Overview and ROI |
| `2` | Targets versus achieved |
| `3` | Purchasing and suppliers |
| `4` | Operations and bottling |
| `5` | Supply chain: components and products |
| `6` | Sales and customers |
| `7` | How we modelled it |
| `8` | What we would change |

Left and right arrows move between views. The round selector in the header re-reads every single-round figure at the chosen round, while trend charts continue to show all seven. It defaults to Round 6.

Any table heading marked with a sort arrow is clickable and keyboard-operable — useful for ranking suppliers, customers, components or products live during questions.

## Presenting from it

- Have the dashboard open in a second window **before** you start, and switch with alt-tab rather than clicking a link. A link that fails to load is the one thing you can't recover from mid-sentence.
- The number keys are the point. Whoever is speaking should press their own key rather than asking someone else to navigate.
- Every view prints to its own page if you need a paper backup (`Ctrl/Cmd + P`).

## Where the numbers come from

Every figure is taken from the simulation's own result export and embedded in the file as a single `DATA` object. Nothing is estimated, smoothed or filled in. Derived quantities — raw-material cost share, gross margin per round, ROI contribution, landed cost, component criticality, the profit bridge — are all computed in JavaScript from that object rather than typed in, so a label can never disagree with the chart beside it.

Three consistency assertions run automatically on load:

- product gross margin sums to total gross margin
- customer contracted revenue sums to total contracted revenue
- purchase value plus production costs equals cost of goods sold

If any of them fail, a red banner appears at the top of the page instead of failing silently. On the shipped data all three pass at every round.

Round 0 is the inherited starting position the team took over, not one of their decisions, and is labelled as such throughout.

## Restyling it

All colours, spacing, radii, shadows and the type scale live in the `:root` block at the top of the `<style>` section. Change them there and the whole dashboard follows. Nothing downstream hardcodes a colour value.

The charts are hand-drawn inline SVG generated by plain JavaScript — no charting library — so they can't fail to load, but it also means new chart types need to be written rather than configured. The existing primitives are `lineChart`, `barChart` (supports diverging and highlighted bars), `stackedBar`, `hBarChart`, `waterfall`, and `makeTable`.

## Accessibility

Every chart carries an `aria-label` and a visually hidden data table, so the content is reachable without seeing the graphic. Data points expose values on hover and on focus. Focus rings are visible throughout, and `prefers-reduced-motion` disables the background animation.

## Known limitations

- **Below about 1400px wide, the widest tables scroll horizontally.** They're fully readable, but you may need to drag. The layout is tuned for 1920×1080 projection; on a laptop, some tables will need a sideways scroll.
- The sidebar hides below 1100px. This is a presentation tool, not a mobile app.
- The round selector changes single-round values, but a handful of tiles are inherently Round-6 specific (the contracted-versus-attained index validation, for instance) and are labelled accordingly.
